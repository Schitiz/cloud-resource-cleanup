## Coding summary

**Rung OCI-3: `crc/oci/spot_vm.py` is now the subpackage `crc/oci/spot_vm/` with a registered `Cleaner` (`@register("oci", "spot_instances")`). Status: done, `make check` green (ruff, mypy strict, lint-imports, pytest).**

- **What changed.** The module (330 lines on main, over the 400-line limit once typed) is split by responsibility, each module with its place in `crc/oci/spot_vm/README.md`: `client.py` (typed Protocols `ComputeClient` / `BlockClient` of the six OCI calls used, `RegionClients`, factories on top of `Base`), `decide.py` (state, preemptible, OKE, tag and age checks through `crc.core.policy` and `crc.core.age`), `leftovers.py` (attachment discovery, wait for `TERMINATED`, volume tag check and delete), `cleaner.py` (`SpotVmCleaner`: read-only `plan()`, mutating `apply()`, summary log, registry factory) and `adapter.py` (`SpotVM`). `crc.oci.spot_vm` still exports `SpotVM` (and `oci`, `Base`, which the existing tests patch). `SpotVM` keeps its constructor (plus an optional trailing `runtime: SpotVmRuntime | None`), attributes (`instance_names_to_delete`, `volumes_to_delete`, `dry_run`, `filter_tags`, `exception_tags`, `age`, `custom_age_tag_key`, `notags`, `default_instance_state`, the two wait constants), `get_deleted`, `delete_count`, `get_deleted_volumes`, `delete()` and the private hooks the legacy tests call (`_is_preemptible`, `_is_managed_or_oke_node`, `_has_matching_filter_tags`, `_attached_block_volume_ids`, `_wait_instance_terminated`, `_volume_ok_to_delete`, `_delete_volume`); it still subclasses `Service` and `Base` and `crc.py` is unchanged. The SDK clients satisfy the Protocols structurally; paging goes through an injected `Pager` (default `oci.pagination.list_call_get_all_results`, looked up at call time, so tests that patch it keep working). Filtering: `policy.state_in`, `policy.oci_is_managed_or_oke_node`, `policy.should_skip_by_tags` (exception any, notags all, untagged never protected), `policy.filter_tags_all_keys`; age: `core_age.validated_retention_age` (fail closed), `policy.effective_age`, `core_age.is_old`. The factory calls `core_age.require_positive_age` like `SpotVM.__init__`.
- **Cleaner flow.** `plan()` lists regions and instances, applies the checks in the order of main and reads the attached volumes of each candidate (a failed attachment read keeps the instance and logs the same two error lines); in a dry run it also tag-checks the leftover volumes and logs main's summary. `apply()` terminates (`preserve_boot_volume=False`), waits for `TERMINATED` when volumes were attached, then tag-checks and deletes each volume, instance by instance; it logs the summary. `Result.related["Disk"]` holds the leftover volumes. Per-instance errors are logged and isolated exactly as on main.
- **Parity.** `tests/legacy/oci_spot_vm.txt` is the exact `git show main:crc/oci/spot_vm.py`. `tests/test_oci_spot_instances_parity.py` runs 94 cases (dry run, state, preemptible, OKE tags / defined tags / metadata, filters, exception tags, notags, untagged, age edges, `MAX_AGE`, custom age tag variants, region and client errors, attachment list failures, detached attachments, volume tag checks, volume get and delete errors, terminate errors, wait polling / 404 / error / timeout with a fake monotonic clock, region-listing errors: connectivity and auth fall back to `us-sanjose-1`, unexpected errors propagate) twice (the `SpotVM` adapter and the registered Cleaner via `plan()` then `apply()`), plus a repeated-`delete()` test and a 28-row quirk table. The adapter matches main on SDK calls in order, results, volumes, log records, stdout and errors. The Cleaner path matches on results, stdout, error type and message, per-call-name SDK sequences, the mutating and wait/volume-check sequence, the log records (multiset), the summary lines (tail, same text as main) and the order of the plan and apply log groups. Differences by design, Cleaner path only: all attachment reads precede the terminate calls, so per-instance log lines are not interleaved; an error raised by `get_all_regions` or the factory (age validation) surfaces from `plan()` / the factory before any mutation; if a volume tag check raised mid-way in a dry run (it cannot with valid specs) the instance would not be listed, whereas main would already have appended its name.
