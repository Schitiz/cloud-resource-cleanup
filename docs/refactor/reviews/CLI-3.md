# CLI-3 review

## Coding summary

Rung CLI-3: `main()` moved from `crc.py` into `crc/cli/`, `crc.py` is a thin entry point and is off the ruff ratchet. No behaviour change.

- **Summary.** `crc/cli/` gained, each file under 400 lines, ruff clean and mypy strict (`crc.cli` is in no exemption list): `main.py` (`main()`, composes the rest in the order of `main`), `inputs.py` (`Options`, `Tokens`, `Targets` frozen dataclasses; `read_options`, `read_tokens`, `check_tokens`, `check_flag_combinations`, `resolve_targets`, `validate_values`), `clients.py` (`build_slack_client`, `build_influxdb_client` with the InfluxDB field check right before the client, `set_max_age` / `reset_max_age` with their prints), `context.py` (`RunContext` and `make_crc`, the single place that builds `CRC(...)` positionally with the 9 arguments of `main`), `scan.py` (`run_scan` and its helpers: console URL, hit normalisation, scan call, Slack or console report; always `sys.exit(0)`) and `dispatch.py` (`run_dispatch`, one handler per resource in a `HANDLERS` table, the AWS disk opt-in breaker in `_disk`, the three spot warnings, the `Snapshot` branch). Order of errors, prints, log lines, fake-call order and exit behaviour are as in the oracle. `crc.py` keeps the copyright line, imports `main` from `crc.cli.main`, re-exports every name the four path-loading tests and the CLI contract need (`__all__` lists them) and ends with `if __name__ == "__main__": main()`. `pyproject.toml`: `"crc.py"` removed from the ruff `extend-exclude` (only edit); `make check` runs ruff on `crc.py` and it is clean. The mypy `exclude = ['^crc\.py$']` is left as is because a top-level `crc.py` and the `crc` package clash for mypy. `crc/cli/README.md` (four ARCH-002 sections) and `crc/README.md` (cli entry and `crc.py` description) updated. Two deliberate textual equivalences: `EnvironmentError` is written `OSError` (the same class, ruff UP024), and `resources == "kms" or resources == "all"` is `in ("kms", "all")` (same `==` semantics, no hashing). The dead `clouds == "all"` branch of the scan list (BUG-038) became `list(targets.clouds)`, what it always evaluated to.
