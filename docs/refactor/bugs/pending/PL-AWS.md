| NEW | A connectivity error from the single `describe_regions` call (or from creating the client) in the default region replaces the account's region list with botocore's static list (`Session().get_available_regions`). That list contains opt-in regions the account has not enabled and ignores account state, so every later per-region call in such a region fails (typically an auth error), which aborts the run in modules that propagate non-connectivity errors (cases `fallback-describe-endpoint`, `fallback-client-creation-endpoint`) | `crc/aws/_base.py:33-43` | yes | run fails | low | PL-AWS | open |
| NEW | `get_all_regions` has no retry: one transient timeout on the only `describe_regions` call switches the whole run to the static list (see the previous row), and the WARNING `describe_regions failed for ... using boto3 static region list` is the only trace (cases `fallback-describe-read-timeout`, `fallback-describe-closed`) | `crc/aws/_base.py:26-43` | yes | run fails | low | PL-AWS | open |
| NEW | `botocore.exceptions.SSLError` (certificate or TLS failure) is a subclass of `botocore.exceptions.ConnectionError`, so it is in `CONNECTIVITY_ERRORS` as well: a TLS or proxy-certificate problem is treated as an unreachable region (static fallback in `get_all_regions`, a skipped region in the cleaners) instead of failing the run | `crc/aws/connectivity.py:10-21` (`BotoConnectionError` at `:12`, tuple `:17-21`), used `crc/aws/_base.py:33` | yes | keeps what it should delete | low | PL-AWS | open |
